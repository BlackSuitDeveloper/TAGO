2. 세부 코드 라인 바이 라인 해설

2.1. 좌석 매퍼 & 조건부 선점 쿼리 (SeatMapper.java / SeatStatusUpdateDTO.java / seat_mapper.xml)

동시성 충돌을 원천 차단하고 좌석 상태를 원자적(Atomic)으로 갱신하는 데이터 접근 계층입니다. 다수의 파라미터를 개별 전달하는 대신 전용 DTO(SeatStatusUpdateDTO)로 캡슐화하여 인자 순서 오류 방지 및 유지보수성을 극대화했습니다.

// 1. 전용 DTO 캡슐화 (Parameter Object Pattern 적용)
@Data

@NoArgsConstructor

    // 동시성 제어 핵심: 전용 DTO를 수신하여 현재 상태(currentStatus)가 일치할 때만 조건부 갱신
    int updateSeatStatusConditional(SeatStatusUpdateDTO dto);

    int updateSeatStatusBySeq(@Param("seatSeq") Long seatSeq, @Param("newStatus") String newStatus);

<!-- seat_mapper.xml : 조건부 UPDATE 쿼리 -->
<update id="updateSeatStatusConditional" parameterType="com.kedu.tago.seat.dto.SeatStatusUpdateDTO">
    UPDATE seat
    SET status = #{newStatus},
        version = version + 1
    WHERE schedule_seq = #{scheduleSeq}
      AND car_no = #{carNo}
      AND seat_no = #{seatNo}
      AND status = #{currentStatus}
</update>
💡 핵심 코드 분석:
  • DTO 캡슐화 (Clean Code 준수): 파라미터가 5개에 달할 경우 메서드 시그니처가 복잡해지고 인자 전달 순서 변경에 따른 버그가 생기기 쉽습니다. SeatStatusUpdateDTO 객체로 묶어 빌더 패턴(builder())으로 명확히 주입하여 타입 안정성과 가독성을 획기적으로 개선했습니다.
  • WHERE status = #{currentStatus} (AVAILABLE): 동일 좌석에 수많은 사용자가 동시에 클릭하여 선점을 요청하더라도, 데이터베이스 행 잠금(Row Lock)에 의해 최초 1건만 행을 갱신하고 반환값 1을 얻습니다.
  • 그 뒤에 도달한 요청들은 이미 상태가 HELD로 바뀌었으므로 조건에 일치하지 않아 반환값 0을 받게 되며, 서비스 계층에서 즉시 중복 예매 방지 예외(409 Conflict)를 발생시킵니다.
  • version = version + 1: 낙관적 락(Optimistic Lock) 추적 컬럼을 갱신하여 데이터 무결성을 보장합니다.

2.2. 실시간 좌석 SSE 스트림 (SeatService.java & SeatController.java)

HTTP Server-Sent Events(SSE) 기술을 적용하여 별도의 폴링 없이도 좌석 선점/발권 상태가 모든 접속자 화면에 즉각 반영되도록 구현했습니다.

// SeatService.java 중 SSE 구현부
private final Map<Long, List<SseEmitter>> sseEmitters = new ConcurrentHashMap<>();

public SseEmitter subscribeSeatStream(Long scheduleSeq) {
    SseEmitter emitter = new SseEmitter(60 * 1000L * 30); // 30분 타임아웃
    List<SseEmitter> list = sseEmitters.computeIfAbsent(scheduleSeq, k -> new CopyOnWriteArrayList<>());
    list.add(emitter);

    emitter.onCompletion(() -> list.remove(emitter));
    emitter.onTimeout(() -> list.remove(emitter));
    emitter.onError(e -> list.remove(emitter));

    try {
        emitter.send(SseEmitter.event().name("INIT").data(Map.of("message", "SSE connected for scheduleSeq " + scheduleSeq)));
    } catch (IOException e) {
        list.remove(emitter);
    }
    return emitter;
}

public void broadcastSeatStatusChange(Long scheduleSeq, Integer carNo, String seatNo, String newStatus) {
    List<SseEmitter> list = sseEmitters.get(scheduleSeq);
    if (list == null || list.isEmpty()) return;

    Map<String, Object> payload = Map.of(
            "scheduleSeq", scheduleSeq, "carNo", carNo, "seatNo", seatNo, "status", newStatus
    );
    for (SseEmitter emitter : list) {
        try {
            emitter.send(SseEmitter.event().name("SEAT_UPDATE").data(payload));
        } catch (IOException e) { list.remove(emitter); }
    }
}
💡 핵심 코드 분석:
  • ConcurrentHashMap & CopyOnWriteArrayList: 다중 스레드 환경에서 구독자 추가/제거 시 동시성 충돌(ConcurrentModificationException)을 방지합니다.
  • broadcastSeatStatusChange(): 누군가 좌석을 선점하거나 결제를 마쳤을 때 해당 기차 스케줄을 보고 있는 모든 브라우저에 SEAT_UPDATE 이벤트를 전송하여 즉각 회색(선택 불가)으로 전환시킵니다.

2.3. 대기열 시스템 (QueueService.java)

명절/출퇴근 급격한 트래픽 몰림에 대비하여 Redis ZSet 기반 점수(진입시각) 정렬 대기열을 제공하며, 로컬 환경에서 Redis가 꺼져 있어도 서버가 죽지 않고 안전하게 In-Memory 대기열로 Fallback 전환되도록 설계했습니다.

// QueueService.java
public QueueResponseDTO enterQueue(Long scheduleSeq, String memberId) {
    String token = UUID.randomUUID().toString();
    long now = System.currentTimeMillis();

    if (redisTemplate != null) {
        try {
            String queueKey = QUEUE_KEY_PREFIX + scheduleSeq;
            // ZADD NX : 이미 존재하는 토큰의 점수는 덮어쓰지 않고 보호
            redisTemplate.opsForZSet().addIfAbsent(queueKey, token, now);
            Long rank = redisTemplate.opsForZSet().rank(queueKey, token);

            if (rank != null && rank < ALLOWED_BURST_COUNT) {
                redisTemplate.opsForSet().add(ADMITTED_SET_KEY, token);
                return QueueResponseDTO.builder().queueToken(token).queueRank(0L).isAvailable(true).build();
            }
            return QueueResponseDTO.builder().queueToken(token).queueRank(rank + 1).isAvailable(false).build();
        } catch (Exception e) {
            log.warn("Redis 접속 불가, 인메모리 대기열로 Fallback: {}", e.getMessage());
        }
    }
    // Fallback: ConcurrentSkipListMap 기반 인메모리 처리
    inMemoryQueue.put(token, now);
    return QueueResponseDTO.builder().queueToken(token).queueRank((long) inMemoryQueue.size()).isAvailable(false).build();
}

2.4. 좌석 선점 및 TTL 자동 회수 (ReservationService.java)

사용자가 선택한 좌석을 선점(HELD)하고 예약 레코드를 생성하며, 결제하지 않고 이탈 시 5분 후 자동으로 좌석을 반환하는 핵심 비즈니스 로직입니다.

@Transactional
public ReservationResponseDTO holdSeats(ReservationRequestDTO request, String memberId) {
    Long scheduleSeq = request.getScheduleSeq();
    Integer carNo = request.getCarNo();
    List<String> seatList = request.getSeatList();

    // 1. 운행 요금 조회 (기본 운임 59,800원)
    ScheduleResponseDTO schedule = scheduleService.getScheduleDetail(scheduleSeq);
    int unitPrice = (schedule.getStandard_price() != null && schedule.getStandard_price() > 0)
            ? schedule.getStandard_price().intValue() : 59800;
    int totalPrice = unitPrice * seatList.size();

    LocalDateTime now = LocalDateTime.now();
    LocalDateTime expiresAt = now.plusMinutes(5); // 선점 유효시간 5분 설정

    List<Long> createdReservationSeqs = new ArrayList<>();
    for (String seatNo : seatList) {
        SeatDTO seat = seatMapper.selectSeat(scheduleSeq, carNo, seatNo);

        // 2. DTO 기반 조건부 UPDATE 실행 (동시성 제어: status가 AVAILABLE일 때만 1건 갱신)
        SeatStatusUpdateDTO updateDTO = SeatStatusUpdateDTO.builder()
                .scheduleSeq(scheduleSeq).carNo(carNo).seatNo(seatNo)
                .currentStatus("AVAILABLE").newStatus("HELD").build();
        int updated = seatMapper.updateSeatStatusConditional(updateDTO);
        if (updated == 0) {
            throw new ResponseStatusException(HttpStatus.CONFLICT, "좌석 " + seatNo + "은(는) 이미 선택되었거나 예약 진행 중입니다.");
        }

        // 3. reservation 레코드 저장
        ReservationDTO reservation = ReservationDTO.builder()
                .memberId(memberId != null ? memberId : "guest")
                .scheduleSeq(scheduleSeq).seatSeq(seat.getSeatSeq())
                .status("HELD").totalPrice(unitPrice)
                .reservedAt(now).expiresAt(expiresAt).build();

        reservationMapper.insertReservation(reservation);
        createdReservationSeqs.add(reservation.getReservationSeq());

        // 4. SSE 브로드캐스트로 다른 사용자 화면에 선점 상태 즉시 전파
        seatService.broadcastSeatStatusChange(scheduleSeq, carNo, seatNo, "HELD");
    }
    return ReservationResponseDTO.builder().reservationSeq(createdReservationSeqs.get(0)).totalPrice(totalPrice).status("HELD").expiresAt(expiresAt).build();
}

// R003: 5초 주기로 만료된 선점 좌석 자동 회수
@Scheduled(fixedDelay = 5000)
@Transactional
public void autoReclaimExpiredHeldSeats() {
    List<ReservationDTO> expiredList = reservationMapper.selectExpiredHeldReservations();
    for (ReservationDTO r : expiredList) {
        reservationMapper.updateReservationStatus(r.getReservationSeq(), "CANCELLED", "TTL_EXPIRED");
        seatMapper.updateSeatStatusBySeq(r.getSeatSeq(), "AVAILABLE");
    }
}
💡 핵심 코드 분석:
  • expiresAt = now.plusMinutes(5): 사용자가 결제창에 머무르는 동안 선점권을 5분간 보장합니다.
  • autoReclaimExpiredHeldSeats(): 사용자가 결제하지 않고 브라우저를 닫아버려도 스케줄러가 expires_at < NOW() 조건의 레코드를 찾아 TTL_EXPIRED 사유로 취소하고 좌석을 즉시 AVAILABLE로 돌려놓아 다른 사용자가 다시 예매할 수 있게 만듭니다.

2.5. 결제 및 승차권 발권 확정 (PaymentService.java)

클라이언트 금액 위조 방지 검증, 승차권 티켓 번호 생성 및 CONFIRMED 단일 트랜잭션 확정 로직입니다.

@Transactional
public PaymentResponseDTO processPayment(PaymentRequestDTO request, String memberId) {
    Long reservationId = request.getReservationId();
    Integer requestedPrice = request.getTotalPrice();

    ReservationDTO reservation = reservationMapper.selectReservationById(reservationId);
    if (reservation == null) throw new ResponseStatusException(HttpStatus.NOT_FOUND, "예약 내역이 없습니다.");

    // 1. 상태 및 5분 만료 여부 검증
    if (!"HELD".equals(reservation.getStatus())) throw new ResponseStatusException(HttpStatus.BAD_REQUEST, "결제 가능한 선점 상태가 아닙니다.");
    if (reservation.getExpiresAt().isBefore(LocalDateTime.now())) throw new ResponseStatusException(HttpStatus.GONE, "선점 시간이 만료되었습니다.");

    // 2. 클라이언트 금액 변조 검증 (P001)
    if (requestedPrice != null && !requestedPrice.equals(reservation.getTotalPrice())) {
        throw new ResponseStatusException(HttpStatus.BAD_REQUEST, "결제 금액이 위조되었거나 일치하지 않습니다.");
    }

    // 3. 16자리 승차권 발권 번호 생성 (예: 1029-3847-5690-11)
    String ticketNumber = String.format("%04d-%04d-%04d-%02d",
            ThreadLocalRandom.current().nextInt(1000, 10000),
            ThreadLocalRandom.current().nextInt(1000, 10000),
            ThreadLocalRandom.current().nextInt(1000, 10000),
            ThreadLocalRandom.current().nextInt(10, 100));

    // 4. 결제(Payment) 레코드 생성 (APPROVED)
    PaymentDTO payment = PaymentDTO.builder()
            .reservationSeq(reservationId).orderId(ticketNumber)
            .paymentKey("MOCK_PG_" + UUID.randomUUID().toString().substring(0, 12))
            .amount(reservation.getTotalPrice()).status("APPROVED")
            .requestedAt(now).approvedAt(now).build();
    paymentMapper.insertPayment(payment);

    // 5. 예약(Reservation) 및 좌석(Seat) 상태를 CONFIRMED로 단일 트랜잭션 확정
    reservationMapper.confirmReservation(reservationId);
    seatMapper.updateSeatStatusBySeq(reservation.getSeatSeq(), "CONFIRMED");

    return PaymentResponseDTO.builder()
            .paymentSeq(payment.getPaymentSeq()).ticketNumber(ticketNumber)
            .status("APPROVED").amount(reservation.getTotalPrice()).build();
}
💡 핵심 코드 분석:
  • requestedPrice != reservation.getTotalPrice(): 클라이언트가 브라우저 개발자 도구 등으로 금액을 0원이나 할인 조작하여 보냈을 때 서버 DB에 저장된 원천 금액과 대조하여 즉시 차단합니다.
  • confirmReservation()과 updateSeatStatusBySeq(..., 'CONFIRMED')가 하나의 @Transactional 범위 내에서 실행되므로 도중에 오류가 발생하면 결제/예약/좌석 상태가 함께 롤백되어 데이터 일관성이 완벽히 유지됩니다.

2.6. 프론트엔드 연동 (ReservationPage.jsx)

프론트엔드 화면에서 백엔드 API와 실시간 SSE 스트림을 연동한 핵심 자바스크립트 코드입니다.

// 1. 호차 선택 시 백엔드 좌석 목록(GET /api/seat) 동기화 & 실시간 SSE 연결
useEffect(() => {
  const fetchSeats = async () => {
    const res = await client.get('/api/seat', { params: { scheduleSeq: bookingInfo.scheduleSeq, carNo: selectedCarNo } });
    const occupied = res.data.seatList.filter(s => s.status !== 'AVAILABLE').map(s => s.seatNo);
    setOccupiedSeatsByCar(prev => ({ ...prev, [selectedCarNo]: occupied }));
  };
  fetchSeats();

  // SSE 구독: 다른 사람의 좌석 선점 실시간 반영
  const eventSource = new EventSource(`http://localhost:80/api/seat/stream?scheduleSeq=${bookingInfo.scheduleSeq}`);
  eventSource.addEventListener('SEAT_UPDATE', (e) => {
    const data = JSON.parse(e.data);
    setOccupiedSeatsByCar(prev => {
      const current = prev[data.carNo] || [];
      return data.status === 'AVAILABLE'
        ? { ...prev, [data.carNo]: current.filter(no => no !== data.seatNo) }
        : { ...prev, [data.carNo]: Array.from(new Set([...current, data.seatNo])) };
    });
  });
  return () => eventSource.close();
}, [bookingInfo.scheduleSeq, selectedCarNo]);

// 2. 결제 버튼 클릭 시 선점(hold) ➔ 결제(pay) 순차 확정
const handleFinalPayment = async () => {
  // 1단계: 좌석 선점 (POST /api/reservation)
  const resHold = await client.post('/api/reservation', {
    scheduleSeq: bookingInfo.scheduleSeq, carNo: selectedCarNo, seatList: selectedSeats.map(s => s.seatId), count: selectedSeats.length
  });
  // 2단계: 결제 및 발권 확정 (POST /api/payment)
  const resPay = await client.post('/api/payment', {
    reservationId: resHold.data.reservationId, payMethod: 'CARD', totalPrice: totalPrice
  });
  alert(`승차권 발권 완료!\n발권 번호: ${resPay.data.ticketNumber}`);
  navigate('/mypage');
};
